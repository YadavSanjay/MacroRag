# 06 — Web UI (setup & operation)

The MacroRAG web UI is a React + TypeScript + Vite app (TanStack Query + Router). It
talks to the FastAPI backend through a dev proxy and surfaces Business, Maintenance
and System screens.

> Audience: technical operators / front-end developers. Non-technical users should
> read [07 – Business User Guide](07-business-user-guide.md).
> Design: [UI design doc](../design/Macro_RAG_UI_Design.md) ·
> [ui/README.md](../../ui/README.md). Containerised deploy of the UI:
> [09 §1](09-packaging-and-deployment.md) and [UI containerization](../design/UI_Containerization.md).

---

## 1. Prerequisites

- The **backend API must be running** (it's what the UI calls):
  ```bash
  python -m pipelines.cli serve            # http://127.0.0.1:8000
  ```
- A **Node toolchain** on `PATH` — node 24.x, npm 11 (the UI image pins
  `node:24.14.0`). Use `npm --prefix ui` rather than `cd ui` so your shell stays at
  the repo root.

---

## 2. Install & run

```bash
# install dependencies (once)
npm install --prefix ui

# start the dev server -> http://localhost:5173
npm run dev --prefix ui
```

Open **http://localhost:5173**. The dev server proxies all `/api/*` requests to the
backend (default `http://127.0.0.1:8000`).

### Pointing the UI at a different backend

The proxy target is the `VITE_API_TARGET` env var (read by `vite.config.ts`):

```bash
# POSIX
VITE_API_TARGET=http://localhost:9000 npm run dev --prefix ui
# PowerShell
$env:VITE_API_TARGET = "http://localhost:9000"; npm run dev --prefix ui
```

### Other npm scripts

| Command | Purpose |
|---|---|
| `npm run build --prefix …\ui` | Typecheck + production build → `ui/dist/` |
| `npm run typecheck --prefix …\ui` | TypeScript check only (no emit) |
| `npm run gen:api --prefix …\ui` | Regenerate the typed API client from the live `/openapi.json` (backend must be running) |

Serve the production build (`ui/dist/`) behind any static host or reverse proxy that
also routes `/api` to the FastAPI server.

---

## 3. The API-key gate

If the backend has auth enabled ([05 §2](05-api-and-integration.md)), the UI prompts
for an API key on first load and stores it in `localStorage` (`macrorag.apiKey`),
sending it as `X-API-Key` on every call. To reach Maintenance/System (admin)
features, enter a key listed in `admin_api_keys`. When backend auth is off, no key is
needed.

## 4. The screens

**Business**
- **Ask** — streaming cited Q&A with an evidence rail and a citation drawer; submit
  thumbs feedback. (Backed by `/query/stream`, `/citations/{id}`, `/feedback`.)
- **Factors** — ranked, cited macro risk factors for a portfolio or theme. (`/factors`.)
- **Scenario Studio** — shock-vector synthesis with the citation-gating view and
  diagnostics, plus compare & export. Options set the horizon, a field subset, the
  expected direction per field and an extra scenario narrative (`synthesis.*`); each
  field shows its grounding mode, evidence horizon and validation codes, and each
  requested-but-missing field says why. (Backed by `mode=synthesize`.)
- **Corpus** — facet browser over documents and the time-series catalog. (`/corpus/*`.)

**Internal maintenance** (admin)
- **Index** — build / append the stores. **Quality** — eval (optionally with the LLM
  judge), drift, self-check, episode backtest, structured-output health, feedback review
  and proposing golden candidates from feedback.
- **Ingestion** — tier catalog + run endpoints. **Curation** — vocabulary (editable and
  persisted via `PUT /admin/vocabulary`, [Production Hardening §E](../design/Macro_RAG_Production_Hardening.md))
  + maintenance jobs. Long tasks run as background **jobs** with live logs (`/admin/*`, `/admin/jobs/*`).

**System (technical)**
- **Map** — component topology + live config/impls. **Traces** — end-to-end waterfall,
  score evolution, evidence drill-down. **Health** — manifest, staleness, activity,
  alerts. **Stores** — vector + time-series inspectors.

> Every nav screen above is live; `ui/src/` is the source of truth for what exists. The
> [UI design doc](../design/Macro_RAG_UI_Design.md) §6 lists what is not built (a series
> chart, full per-stage score evolution, a trace plan view, a command palette).

## 5. Troubleshooting (UI)

| Symptom | Likely cause | Fix |
|---|---|---|
| Blank page / `/api` calls 404 or fail | Backend not running | Start `python -m pipelines.cli serve`; confirm `http://127.0.0.1:8000/healthz` |
| `/api` calls hit the wrong server | `VITE_API_TARGET` not set / wrong | Set `VITE_API_TARGET` and restart `npm run dev` |
| `npm` not found / wrong Node | Toolchain not on PATH | Put node 24.x / npm 11 on `PATH`; invoke with `--prefix ui` |
| 401/403 in the UI | Auth on; missing/non-admin key | Enter a valid key in the gate; for admin screens use an `admin_api_keys` key |
| Ask answers don't stream | SSE blocked by a proxy | Disable buffering for `/query/stream`; in dev rely on the Vite proxy |
| Types out of date after API change | Stale generated client | `npm run gen:api` (backend up), then `npm run typecheck` |
| Maintenance/System screens empty | Backend `/admin/*` disabled or unreachable | Confirm admin endpoints respond; check the API-key gate |
| Production build serves but `/api` 404s | Static host not proxying `/api` | Add a reverse-proxy rule from `/api` → FastAPI |
